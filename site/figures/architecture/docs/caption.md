**Figure — Une campagne traverse sept modules qui rangent les fichiers lourds dans un stockage objet et leur trace dans un catalogue ; la même chaîne tourne sur trois cibles.** **a**, Chaîne d'une campagne, suivie sur `palier2_tg3d` : une grille de 4 × 3 points $(Re, Pm)$ (1) devient douze tâches à identifiant déterministe (2), puis douze simulations MHD 3D à $64^3$ (3 ; la vignette montre $|\mathbf{u}|$ de l'écoulement de Taylor–Green initial), écrites en fichiers MFF compatibles The Well (4). Le jeu de données coupe la grille par point de paramètres (5 ; validation $Re = 100$, $Pm = 1$ ; test $Re = 50$, $Pm = 2$), le modèle génère des potentiels vecteurs dont le rotationnel donne $\mathbf{u}$ et $\mathbf{B}$ (6), et l'évaluation compare les lois générées à la référence (7 ; spectres illustratifs). Chaque étape écrit au catalogue ; les champs et les points de contrôle vont au stockage objet ; la simulation porte le même UUID dans son fichier et au catalogue, si bien que la partie simulations du catalogue se reconstruit à partir des fichiers (`ingest`). **b**, Les mêmes rôles sur trois cibles : portable sans GPU, VM louée avec Docker Compose (ports liés à 127.0.0.1, accès par tunnel SSH), cluster Slurm avec Apptainer, dont les nœuds n'ont pas Internet : ses fichiers sont copiés vers le stockage S3, puis ingérés dans PostgreSQL ; ses modèles et évaluations restent dans le SQLite du cluster. Installation : `make setup`, `sudo infra/deploy/bootstrap_vm.sh`, `make sif` puis `sbatch`.
