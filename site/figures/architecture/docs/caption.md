**Figure — A campaign goes through seven modules that put the heavy files in object storage and their record in a catalog; the same pipeline runs on three targets.** **a**, Campaign pipeline, followed on `stage2_tg3d`: a 4 × 3 grid of $(Re, Pm)$ points (1) becomes twelve tasks with deterministic identifiers (2), then twelve 3D MHD simulations at $64^3$ (3; the thumbnail shows $|\mathbf{u}|$ of the initial Taylor–Green flow), written as MFF files compatible with The Well (4). The dataset splits the grid by parameter point (5; validation $Re = 100$, $Pm = 1$; test $Re = 50$, $Pm = 2$), the model generates vector potentials whose curl gives $\mathbf{u}$ and $\mathbf{B}$ (6), and the evaluation compares the generated distributions with the reference (7; illustrative spectra). Every stage writes to the catalog; fields and checkpoints go to object storage; a simulation carries the same UUID in its file and in the catalog, so the simulations part of the catalog can be rebuilt from the files (`ingest`). **b**, The same roles on three targets: a laptop without GPU, a rented VM with Docker Compose (ports bound to 127.0.0.1, access through an SSH tunnel), and a Slurm cluster with Apptainer whose nodes have no Internet access: its files are copied to S3 storage, then ingested into PostgreSQL; its models and evaluations stay in the cluster's SQLite. Setup: `make setup`, `sudo infra/deploy/bootstrap_vm.sh`, `make sif` then `sbatch`.
