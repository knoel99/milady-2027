# AGENTS.md

Instructions for any AI coding agent working in this repository, whatever its provider. Tool-specific files (`CLAUDE.md`, `.claude/agents/`) are thin adapters around this file and `agents/`. Talk to the user in French; write everything in the repository in English.

## The project

An English-only Quarto site preparing the M2 internship MilaDy 2027 (physics-constrained generative models of parametric dynamical systems: MHD, dynamo, conditional flow matching). `site/` holds eight preparation modules (`prep/`), a **prospective** internship report (`report/`), a PhD proposal (`thesis/`) and pages on the supervisors, experiments, computing and interactive diagrams. `experiments/` holds the CPU experiments E1–E3. `src/milady/`, `tests/` and `infra/` are the HPC package planned for the thesis. `research/` will hold the hypothesis register and the lab journal. Page paths given to tools (`prep/p3-mhd-dynamo`, `report`) are relative to `site/`.

The site is built and published by `.github/workflows/pages.yml` on every push to `main`; rendered `index.html` files are not versioned. `.github/workflows/tests.yml` runs `make test`'s pytest selection, `ruff check src tests` and `tools/sync_agents.py --check` on every push to `main` and every pull request.

## Sources of truth

Read before writing a page:

- `docs/specs/page-contract.md`: mandatory module structure (anchors `{#objectives}`, `{#prerequisites}`, `{#plan}`, `{#exercises}`, `{#internship-link}`, `{#further-reading}`, `{#sources}`), callouts, KaTeX rules, code, figures, style.
- `docs/specs/notation.md`: notation shared by all pages.
- `docs/specs/theory-brief.md`: the statements and proofs (Propositions 1–9) shared by the report and the thesis, the E1–E3 plan, and what is already published (cite it, never claim it).
- `docs/specs/sources/*.md` (`literature`, `dynamo`, `supervisors`, `data-metrics`): the only allowed source for facts about the literature, the supervisors, the offer and the project. Tags `[verified]`, `[corrected: …]`, `[UNCONFIRMED]`; never use an `[UNCONFIRMED]` entry without a new check.
- `docs/review-2026-11.md`: open corrections from the November 2026 review.

Always distinguish what is **measured in this repository**, **published** (with a reference) or **conjectured**. Numbers about experiments come only from `experiments/results/digest.md`, generated by `experiments/digest.py` from the JSON results.

## Commands

```bash
python3 tools/new_page.py prep/<id> "Title" "Subtitle"   # page skeleton (generated header: do not edit it)
python3 tools/render.py report prep/p3-mhd-dynamo         # render pages; --all for the whole site
python3 tools/check_gates.py [page …]                     # sections, ≥ 10 ★ exercises per module, links, anchors
NODE_PATH=<node_modules with katex@0.19.0> node tools/check_katex.mjs $(find site -name index.html)
cd experiments && python3 e1_gissinger.py --quick         # also e2_data.py, e2_mhd2d.py, e3_abc.py; figures.py; digest.py > results/digest.md
experiments/run_stage.sh [--quick] [--seeds "0 1 2 3 4"]  # E1-E3 with several seeds, one process per seed, then figures and digest
make test                                                 # pytest for src/milady
python3 -m ruff check src tests                           # lint, as in CI
python3 tools/sync_agents.py [--check]                    # regenerate tool-specific agent files from agents/roles/
```

- Never edit an `index.html` by hand: `tools/render.py` restores the pinned KaTeX tags (SRI) that Quarto strips.
- After changing a page, render it and run `check_gates.py` on it.
- `python` blocks in pages are not executed by Quarto: each must run alone in < 30 s on CPU, with its output copied as a comment.
- `--quick` outputs (`results/*_quick.*`, `site/experiments/figures/*_quick.*`) are git-ignored; pages cite full runs only.

## Agents

The roles are defined once, provider-neutral, in `agents/roles/*.md`: a header with an abstract model `tier` (`frontier`, `standard`, `light`), a `reasoning` level (`low`, `medium`, `high`, `max`), `read_only`, `needs` and `max_turns`, then the mandate. `agents/providers.toml` maps tiers and levels to each provider's models; `tools/sync_agents.py` generates the tool-specific files (today `.claude/agents/*.md`). Edit the roles, never the generated files. A tool without sub-agents runs a role as a separate session, with the body of the role file as its prompt. Running a checking role on another provider than the main session is allowed and gives a more independent check.

- **Main session**: the intern, then the PhD student. It reads, states hypotheses, writes code, runs computations, writes and arbitrates.
- **`encadrant`**: tries to refute a result or a protocol (re-runs the script, changes the seed, recomputes the aggregate, tests the edge case, checks the numerical protocol); one verdict per criterion; never edits.
- **`physicien`**: physical intuition; proposes at most three ranked conjectures (orders of magnitude, limiting cases, toy model), each with a refutation criterion, protocol and cost; the user chooses; never edits.
- **`biblio`**: prior art for a claim, lifts `[UNCONFIRMED]` tags, drafts reading notes; the main session writes them into `docs/specs/sources/`.
- **`jury-externe`**: milestones only (theory brief, report v1, thesis v1); a verdict per claim and a pre-defence report.

## Hardcore rules

1. Every requirement has an owner: the user. Agents do not create requirements.
2. No hypothesis without a quantitative refutation criterion written before the computation.
3. `--quick` first; a full run takes at most 2 h, otherwise split it by seed.
4. At least five seeds for any comparison that is quoted.
5. Two cycles without a discriminating verdict: drop the hypothesis and report it as a negative result.
6. Agents do not hold discussions: they write to the register; data decides, otherwise the user does.
7. Budget: at most three sub-agent calls per hypothesis; reasoning `max` only for `jury-externe`, `high` for `physicien`; `medium` by default. When the usage limit warns, finish the current hypothesis, commit and stop.
8. A rule that a script can check belongs in a script (`tools/`, `experiments/digest.py`, tests, CI), not only in prose.

## Model and reasoning level

At the start of each new task, check the session's model and reasoning level. If they do not fit the task, say so in one line (advised tier and level, reason, how to change them in the current tool) and carry on unless the task is long or costly. Say nothing when the setting fits.
