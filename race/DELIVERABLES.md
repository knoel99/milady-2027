# Deliverables of a team

Owned by the user; agents never edit this file. Each team (`claude`, `cursor`, …) delivers, under `site/teams/<team>/`, an internship report and an explorer of its scientific and numerical work, published with the site on GitHub Pages and as a PDF. `python3 tools/check_deliverables.py --team <team>` checks every rule below that a script can check; it must pass before the final report (`research/race-report.md`) is written. Build the deliverables as the work goes, not at the end: they are reviewed by the `jury-externe` at the dates `tools/review_due.py` names (`site/` is in `[reviews]` `jury_watch`).

## 1. Internship report: `site/teams/<team>/report/index.qmd`

The report the offer asks for (`docs/specs/sources/supervisors.md` §1.2 a): physics-constrained generative models (diffusion or flow matching) of parametric 3D fields, constraints imposed through model design, training losses or sampling procedures, evaluated with energy spectra, helicity, divergence control and topology preservation, leading to a **comparative study** and **code integrated into the project toolbox**. It reports what the team measured, written as a classic M2 internship report (about 30 to 50 pages in PDF, English).

- **Two outputs from one source.** HTML in the style of the site (copy the `format: html` block of `site/report/index.qmd`, links adjusted) and a classic LaTeX PDF: a `format: pdf` block with `documentclass: report` (or `scrreprt`), `toc: true`, `number-sections: true`, `papersize: a4`, `fontsize: 11pt`, `pdf-engine: xelatex` or `lualatex`, `cite-method: biblatex` or the default citeproc. `tools/render.py teams/<team>/report` writes `index.html` and `index.pdf`; the PDF is committed (at most 20 MB) and published next to the HTML, and the HTML links to it.
- **Sections**, with these anchors: `{#abstract}`, `{#introduction}`, `{#state-of-the-art}`, `{#methods}`, `{#experiments}`, `{#results}`, `{#comparative-study}` (one table: mechanism or model family × metric, mean ± SE over ≥ 5 seeds, verdict of each registered hypothesis), `{#toolbox}` (what entered `src/milady/`, with its tests and how to call it), `{#discussion}` (negative results and refuted claims included), `{#conclusion}`, `{#references}`, `{#reproducibility}` (commands, commits, GPU jobs of `research/compute-ledger.jsonl`, costs).
- **Status of every claim**: measured in this repository (with the digest or result file), published (with a reference from `docs/specs/sources/`), or conjectured. The words *measured*, *published* and *conjectured* appear where they apply.
- **Numbers** only from `experiments/results/digest.md` or a result file generated by a committed script (`AGENTS.md`).

## 2. Figures: many, of two kinds

- **Scientific schematics, with the `schematic-figure` skill** (install: `bash tools/install_skills.sh`; Node.js ≥ 22 and Chromium): at least **8**, each in `site/teams/<team>/figures/<name>/` with its source (`figure/figure.js`, `docs/brief.md`, `docs/spec.md`) and outputs `figure/out/<name>.svg` and `.pdf`. Candidates: the parametric MHD problem and the dynamo; the generative pipeline (data → latent Fourier modes → conditional flow → decoder); each constraint mechanism (design, loss, sampling) on one shared glyph set; the metrics (spectra, helicity, divergence, null points); the protocol (training, validation and held-out parameter values, seeds, floors); the main results as annotated summary panels; the compute path (session → RunPod pod → results). The HTML uses the SVG, the PDF the PDF.
- **Architecture and workflow diagrams, with Archify** (`node .claude/skills/archify/bin/archify.mjs`, or `.cursor/skills/…`): at least **3** standalone HTML diagrams in `site/teams/<team>/diagrams/`: the code architecture of what was added to `src/milady/` (code-backed), the experiment workflow (scripts, data, GPU jobs, digest), and the agent organisation of the team (main session, roles, reviews, tools). Each is linked from the report and the explorer; the PDF includes a static export (PNG or SVG) of each.
- **Data plots** (spectra, helicity, null counts, energy-distance ratios, restart drift) come from committed scripts reading the result files, as SVG or PNG, at least **8**.
- Every figure has a caption that says what it shows and, for data, which file it comes from; every figure file is referenced by the report or the explorer.

## 3. Explorer: `site/teams/<team>/explorer/index.qmd`

A static page of the site to look at and play with the work, no server needed:

- **Controls** (Quarto OJS `Inputs`, or plain HTML inputs with JavaScript): parameter value (η or Rm, training, validation and held-out values marked), model variant or constraint mechanism, seed or mean over seeds, metric.
- **Views**: generated against reference for the chosen value and variant (shell spectra of u and B, magnetic helicity, null points per snapshot, energy balance, divergence); the comparative table, sortable, with the verdicts; 2D slices of a few generated and reference 3D fields (precomputed PNG or small arrays, with a slice-index control); the hypothesis register, filterable by status; the GPU jobs and costs.
- **Data**: `site/teams/<team>/explorer/data/`, exported by a committed script `experiments/export_explorer.py --team <team>` from the result files; at most 25 MB in all, 10 MB per file.
- Links to the report, the diagrams, the code and the digest.

## 4. Publication

The site is built and deployed by `.github/workflows/pages.yml` on every push to `main`; it installs LaTeX when a page declares `format: pdf`. A team's branch reaches `main` only when the user merges it: before the final report, the team checks locally `python3 tools/render.py teams/<team>/report teams/<team>/explorer`, `python3 tools/check_gates.py teams/<team>/report teams/<team>/explorer` and `python3 tools/check_deliverables.py --team <team> --built`. LaTeX in a cloud session: `sudo apt-get update && sudo apt-get install -y --no-install-recommends texlive-latex-recommended texlive-latex-extra texlive-fonts-recommended texlive-xetex lmodern` (or without `sudo` as root).
