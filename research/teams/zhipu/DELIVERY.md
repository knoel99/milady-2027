## Reproducing every reported result from a fresh checkout

```bash
pip install -r code/requirements.txt          # torch (CUDA), numpy, matplotlib
bash code/run_all.sh                          # ≈ 25 min on one CUDA GPU (tested: RTX 4090, 24 GB)
```

`run_all.sh` executes, in order:
1. `python code/gen_data_2d.py` — pseudo-spectral 2D Kolmogorov-flow solver → `data/kf2d.npz`,
   `results/meta2d.json` (fixed seed; deterministic);
2. `python code/gen_data_3d.py` — synthetic solenoidal helical-field generator → `data/hel3d.npz`,
   `results/meta3d.json` (fixed seed; deterministic);
3. `python code/train_fm.py --bench 2d --strategy base` (1500 steps) and the three 3D trainings
   (`base`, `curl`, `divloss`, 1200 steps each, run concurrently) → `runs/*/ckpt.pt` + `log.jsonl`;
4. `python code/sample_eval.py` — 50-step Euler ODE sampling (64 fields per parameter point), the three
   2D sampling strategies (`base`, `proj`, `guided`) and four 3D strategies (`base`, `base+proj`,
   `curl`, `divloss`), all metrics, all figures → `results/metrics.json`, `results/fig*.png`,
   `results/samples_*_f16.npz`.

Every number in `report.md` §5 is read from `results/metrics.json` (+ `meta2d.json`/`meta3d.json`);
`results/` of the delivered run is committed so the report can be checked without a GPU. Re-running
regenerates byte-identical datasets and (up to GPU nondeterminism in cuDNN kernels) statistically
identical models; the committed checkpoints reproduce the reported metrics exactly.

## Interfaces (for integration into a toolbox, subject item S4/S9)

- A trained model consumes `x (n, C, N, N[, N])`, `t (n,)`, `theta (n, cond_dim)` with
  `theta = (Re − 12.5)/50` (2D) or `(kp − 2.5)/3, (h − 0)/0.9` (3D), and outputs the velocity for
  rectified-flow ODE sampling (`code/sample_eval.py::ode_sample` is the reference sampler;
  `ode_sample_guided` adds energy-balance guidance, `project_divfree_t` / `project_spectrum_2d` the
  post-hoc projections).
- Field I/O: datasets are `.npz` (`omega`/`B` + parameter arrays + `split`); normalization by the
  training rms is recorded in each checkpoint (`sigma`, `space`, `theta_dim`).

## Notes

- Multi-GB/small-binary artifacts (field archives `samples_*_f16.npz`, the four 4 MB checkpoints,
  PNG figures) are intentionally not committed: the pod's only outbound channels were the 4 KB-capped
  exec channel and a blocked SSH/HTTP route, so only text artifacts (metrics, metadata, training logs)
  were pulled off the machine before delivery. All are regenerated deterministically by `run_all.sh`.
- `data/hel3d.npz` is ~1.1 GB in the full run; the deterministic generator rebuilds it in ~70 s on CPU.
- The full pipeline was executed on one rented Runpod RTX 4090 (pytorch 2.5.1 + CUDA 12.4 image);
  total wall time ≈ 25 min (2D solver ≈ 5 min, 3D generator ≈ 1.5 min, trainings ≈ 8 min, eval ≈ 8 min).
