## The data set `e4_mhd3d` 1.0

Saturated 3D MHD dynamo in a periodic box, constant ABC force at $k_f = 2$, ν = 0.05 (Re = 10), 16³ grid (every mode
$|m_i| \le 5$ of the solver), 11 magnetic diffusivities η from 0.08 to 0.03 (Rm = 6.25 to 16.7): 6 training, 2 validation and
3 held-out test values. Each file holds 24 trajectories × 100 snapshots (t = 202 to 400, one every 2 time units, after
a transient of 200), the fields `velocity` and `magnetic_field` in float32, and the time series of the solver diagnostics
(energies, injection, dissipations, helicities; transient included). Format: MFF 1.0 (`docs/specs/data-format.md`),
readable as a data set of The Well. Every file passes `validate(..., full_scan=True)`: 11 of 11.

The fields are band-limited: the potentials on which the models are trained are recovered from the stored fields by
`milady.data.convert.e4_latents(path)`, within 1.7e-07 of their root-mean-square value. Largest stored |∇·B|: 5.2e-07.

**Which realisation.** These files are the data generated in the container of the session. The results of the report were
computed on data regenerated on each GPU pod from the same script and seeds; the solver is chaotic and its float32
trajectories differ between processor types, so the two are different draws of the same law. The mean magnetic energy of these
files differs from that of the pod realisation (`experiments/results/e4_reference.json`) by at most 2.5 % over the 11 values of η.

## The cited models

Four laws × five seeds are in the catalogue, each with its evaluations at the three held-out η (source: the committed result
files named in `catalog.json`):

| Law | What it is | Weights |
|---|---|---|
| G0 | Gaussian law, one 8 × 8 covariance per Fourier mode, interpolated in η | closed form: milady.train.constraints.ModewiseGaussian(sign=…).fit(x_train, c_train), refitted from the data set in under 1 s |
| G1 | Gaussian law, full 5320 × 5320 sample covariance per training η, interpolated in η | closed form: milady.train.constraints.FullGaussian(sign=…).fit(x_train, c_train), refitted from the data set in under 1 s |
| W9 | conditional flow matching on the potentials: ResMLP (width 512, depth 4) plus an explicit mode-wise affine term | not kept (the pod of the job was deleted); retrained by the job below in about 1 min per seed on a GPU |
| W16 | samples of W9 sent through the linear map that gives them the mean and covariance of G1 (estimated on 131 072 samples per η) | no weights of its own: W9 plus the map, recomputed at sampling time |

The weights of W9 were not kept. One GPU job writes them (five seeds, about 30 min, under 1 USD at the prices of the pilot;
not run, the pilot being closed to new jobs):

```bash
python3 tools/runpod_job.py run --hours 1.9 --outputs experiments/results/replications/e4_weights -- env E4_SAME_DATA=1 E4_SAVE_MODELS=1 bash experiments/e4_gpu_job.sh full '0 1 2 3 4' e4_weights D
```

## Upload

The session cannot create a GitHub release. From a checkout that holds the files (this container), with the `gh` command
authenticated:

```bash
gh release create e4-data-v1.0 --repo knoel99/milady-2027 --target claude/modest-newton-zx8fqs --title "E4 data set 1.0 (MFF) and catalogue" --notes-file research/release/README.md experiments/data_e4_mff/e4_eta*.h5 research/release/SHA256SUMS research/release/manifest.json research/release/catalog.json research/release/catalog.sqlite
```

To an object store instead, with the catalogue registered at the destination (`MILADY_DB_URL` set):

```bash
PYTHONPATH=src python3 -m milady.data.convert e4 experiments/data_e4 experiments/data_e4_mff --store s3://milady-data --catalog
```

Check after download:

```bash
sha256sum -c SHA256SUMS
```

```bash
PYTHONPATH=src python3 -m milady.data.convert validate --full e4_eta*.h5
```

The container is temporary: if it is reclaimed before the upload, the files are regenerated by `python3 experiments/e4_data.py
--jobs 4` (about 30 min of CPU) and `python -m milady.data.convert e4 experiments/data_e4 experiments/data_e4_mff` (2 min);
the checksums then differ (new identifiers and dates, and another draw on another processor type).
